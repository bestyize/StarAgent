## 0. 背景与目标

### 0.1 现状与痛点

在前面的工具执行系统（Task 1~12）落地后，StarAgent 已经具备了多步执行工具（读写记忆、管理任务、抓取网页）的能力。但在实际多步推理中，模型经常面临以下场景：
1. **歧义分支**：例如用户说"帮我定明天去上海的高铁"，模型检索到了多趟班次，必须由用户拍板车次；
2. **敏感操作确认**：例如用户说"取消所有任务"，模型需要向用户进行二次确认以防误伤；
3. **补充关键缺失参数**：例如需要某个账号或具体日期。

在没有交互确认工具之前，模型只能中断执行并把问题直接写成纯文本回答，导致当前任务循环强行终止。等用户回复时，上下文已经断裂，需要重新发起整个推理。

### 0.2 目标

引入 `request_user_input` 交互确认工具体系：
- **原地挂起**：模型在工具循环中主动提问，会话挂起等待用户作答，拿到答案后无缝继续后续步骤；
- **双模输入卡片**：聊天流内弹出结构化卡片，支持快捷选项单选（2~4 个按钮）与自由输入文本框；
- **长超时看门狗**：打破 30 秒默认工具看门狗，为人类交互提供 5 分钟安全等待时间。

### 1.2 关键交互规则

1. **一问一答，就地冻结**：用户选择某个选项或点击提交后，当前提问卡片立即转换为只读态（显示“已选择：XXX”），输入框与按钮禁用，避免二次重复提交；
2. **多模态合一**：既能点选快捷按钮，也能手打输入文字（二者取其一，点按钮立即作答，输入框点“提交”作答）；
3. **不可逆回溯**：历史会话中已回答的卡片永久保持只读展示，不可再次点击唤起已过期的循环。

## 2. 领域模型与工具契约

### 2.1 消息体扩展（`core:model/Conversation.kt`）

在 `MessageBody` 密封接口中新增 `Question` 消息体：

```kotlin
@Serializable
data class Question(
    val id: String,                             // 提问交互的唯一 ID（如 "q-1"）
    val question: String,                       // 提问内容
    val options: List<String> = emptyList(),     // 快捷选项列表（可选）
    val placeholder: String? = null,            // 输入框占位提示（可选）
    val selectedAnswer: String? = null,         // 最终结果（null 表示等待作答中）
) : MessageBody
```

### 2.2 工具定义扩展（`core:tools`）

#### 增加工具自定义超时能力

在 `Tool` 接口增加可选属性，允许人机交互类工具申请豁免 30s 默认超时：

```kotlin
interface Tool {
    val definition: ToolDefinition
    
    /**
     * 该工具单独声明的执行超时（毫秒）。
     * null 时走循环引擎的默认超时（30,000 ms）。
     * 人机交互类工具（如 request_user_input）可覆盖为更长的等待时间（如 300,000 ms）。
     */
    val timeoutMillis: Long? get() = null
    
    suspend fun execute(args: JsonObject, host: ToolHost): ToolResult
}
```

#### `RequestUserInputTool` 实现

```kotlin
object RequestUserInputTool : Tool {
    override val definition = ToolDefinition(
        name = "request_user_input",
        description = "向用户提出一个需要确认或选择的问题，并挂起等待用户作答。" +
            "当且仅当遇到关键决策分支（如确认班次、确定日期）、需要用户明确授权（如清理/重置操作）、" +
            "或需要用户从多个备选中选择时使用。" +
            "不要拿无关痛痒的问题反复打扰用户。",
        inputSchema = buildJsonObject {
            put("type", "object")
            putJsonObject("properties") {
                putJsonObject("question") {
                    put("type", "string")
                    put("description", "向用户提出的问题文本")
                }
                putJsonObject("options") {
                    put("type", "array")
                    put("description", "供用户快速单选的选项列表（建议 2~4 个），可选")
                    putJsonObject("items") { put("type", "string") }
                }
                putJsonObject("placeholder") {
                    put("type", "string")
                    put("description", "文本输入框的占位提示文字，可选")
                }
            }
            putJsonArray("required") { add("question") }
        },
    )

    // 人类阅读与输入需要时间，给予 5 分钟（300 秒）超时保护
    override val timeoutMillis: Long = 300_000L

    override suspend fun execute(args: JsonObject, host: ToolHost): ToolResult {
        val question = args.stringOrNull("question")
            ?: return ToolResult(callId = "", content = "question 不能为空", isError = true)

        val options = args["options"]?.let { el ->
            (el as? JsonArray)?.mapNotNull { (it as? JsonPrimitive)?.content }
        }.orEmpty()

        val placeholder = args.stringOrNull("placeholder")

        val answer = host.userInput.requestInput(
            agentId = host.agentId,
            question = question.trim(),
            options = options,
            placeholder = placeholder?.trim(),
        )

        return ToolResult(
            callId = "",
            content = "用户给出的回答是：$answer",
        )
    }
}
```

## 3. 挂起与恢复的运行机制

### 3.1 核心数据结构与实现（`core:data/ports/UserInputPortImpl.kt`）

利用 Kotlin 协程的 `CompletableDeferred<String>` 实现内存中高内聚的异步解耦：

```kotlin
class AppUserInputPort(
    private val state: AppState,
) : UserInputPort {

    // 挂起中的提问注册表，Key 为 questionId
    private val pendingInputs = ConcurrentHashMap<String, CompletableDeferred<String>>()

    override suspend fun requestInput(
        agentId: String,
        question: String,
        options: List<String>,
        placeholder: String?,
    ): String {
        val questionId = state.nextId("q")
        val deferred = CompletableDeferred<String>()
        pendingInputs[questionId] = deferred

        try {
            // 向当前对话消息流添加提问卡片
            state.postQuestion(
                agentId = agentId,
                questionId = questionId,
                question = question,
                options = options,
                placeholder = placeholder,
            )

            // 挂起当前协程，等待 UI 操作唤醒
            return deferred.await()
        } finally {
            pendingInputs.remove(questionId)
        }
    }

    /** 响应用户操作，解除挂起 */
    fun submitAnswer(questionId: String, answer: String): Boolean {
        val deferred = pendingInputs[questionId] ?: return false
        return deferred.complete(answer)
    }

    /** 取消某个提问 */
    fun cancelQuestion(questionId: String) {
        pendingInputs[questionId]?.cancel()
    }
}
```

### 3.2 `AppState` 状态管理

```kotlin
fun answerQuestion(agentId: String, questionId: String, answer: String) {
    // 1. 唤醒挂起的执行协程
    userInputPort.submitAnswer(questionId, answer)

    // 2. 找到会话中的 Question 卡片，将 selectedAnswer 更新为 answer
    val conversation = messagesOf(agentId)
    val index = conversation.indexOfFirst {
        (it.body as? MessageBody.Question)?.id == questionId
    }
    if (index >= 0) {
        val oldQuestion = conversation[index].body as MessageBody.Question
        conversation[index] = conversation[index].copy(
            body = oldQuestion.copy(selectedAnswer = answer)
        )
    }

    // 3. 触发持久化
    persistState()
}
```

## 4. 超时与异常处理

### 4.1 超时隔离与多级看门狗

在 `AgentLoop.kt` 中，工具调用超时逻辑适配自定义时长：

```kotlin
val timeout = tool.timeoutMillis ?: DEFAULT_TOOL_TIMEOUT_MILLIS

withTimeoutOrNull(timeout) {
    tool.execute(args, host)
} ?: ToolResult(
    callId = call.id,
    content = "这个操作超时了（超过 ${timeout / 1000} 秒还没有结果）。" +
        "用户未在时限内回应，请根据现有信息继续或告知用户。",
    isError = true,
)
```

1. **当达到 5 分钟超时**：
   - `withTimeoutOrNull` 返回 `null`；
   - `AppUserInputPort` 的 `finally` 块被触发，清理池中的 `CompletableDeferred`；
   - 对话中的卡片标记为超时；
   - 模型收到超时错误结果，自主决定是兜底执行还是结束并向用户汇报。

2. **用户点击界面“停止”按钮**：
   - 触发外部作用域取消，`CancellationException` 抛出；
   - `AgentLoop.execute` 中的 `catch (cancelled: CancellationException)` **原样向上抛出**；
   - 会话状态保留已接收的文字与已完成的卡片，退出忙碌状态。

## 6. 测试策略

遵循 TDD 开发模式，覆盖三个层级的断言：

1. **`core:tools` 单测（`RequestUserInputToolTest`）**：
   - 验证必填字段 `question` 校验；
   - 验证 `options` 与 `placeholder` 正常解析；
   - 验证工具自带的 `timeoutMillis == 300_000L`；
   - 验证返回的模型提示语句格式。

2. **`core:data` 挂起与恢复流程测试（`UserInputFlowTest`）**：
   - 验证挂起恢复：协程 A 调用 `requestInput` 挂起，协程 B 调用 `answerQuestion`，协程 A 正确恢复并拿到回答字符串；
   - 验证会话卡片状态更新：`selectedAnswer` 成功从 `null` 更新为选中的文本；
   - 验证超时：测试注入短超时（如 50ms），验证超时后返回超时提示结果，卡片状态正常清理；
   - 验证取消穿透：外层协程 `cancel()`，`CancellationException` 正常向外抛出。

3. **端到端集成测试（`AgentLoopTest`）**：
   - 模型发出 `request_user_input` 调用的事件，模拟用户作答“确认”，模型在下一轮收到回复后继续输出正文并结束。
