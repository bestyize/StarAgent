## 摘要与战略升级说明

**星环智能 Agent（StarAgent）**最初诞生于移动端手机助手应用。在 v2.0 版本中，项目完成战略跃升——**从一个“单一形态的移动端 App”，全面演进为“一个跨形态、跨平台的通用智能体底座（Agent Substrate & SDK）”**。

通过坚决贯彻**“微内核 + 插件积木（Microkernel Architecture）”**的设计哲学，StarAgent 内核（Core SDK）实现极致克制与无头化（Headless），零 UI 依赖、零平台多余包袱。依托 **Kotlin Multiplatform（KMP）** 的全端原生优势，一套通用内核可无缝装配到多元物理与数字形态中：
- **桌宠机器人（Desktop Pet Robot）**：物理具身动作、表情屏幕、传感器事件、主动好奇心与自发心跳；
- **智能家居中控（Smart Home Gateway）**：无头后台守护、Matter/IoT 原语控制、全双工远场交互；
- **情感陪伴数字人（Emotional Companion）**：拟人心理状态机、长程情景记忆、情绪共鸣与深度关怀；
- **移动随身助理（Mobile Assistant）**：跨应用屏幕自动化操作、离线语音、IM 渠道触达。

一句话概括 v2.0 的产品主张：**以统一的轻量级跨端智能体底座，赋予千行百态的软硬件设备自主思考、情感共鸣与现实行动的能力。**

## 1. 产品定位与战略目标

### 1.1 一句话定义
StarAgent 是一个基于 Kotlin Multiplatform（KMP）的**跨端通用智能体底座与 SDK**，向下解耦异构硬件与操作系统，向上支撑桌宠机器人、智能家居、情感陪伴软件与移动助理等多元产品形态。

### 1.2 战略愿景
打破传统 AI Agent 局限于“屏幕文字输入框”的狭隘现状，让智能体具备全双工语音、物理环境感知、拟人心理状态机与现实工具操作能力，成为开发者构建下一代具身实体与数字伴侣的通用大脑。

### 1.3 核心目标
1. **轻量通用（Core SDK）**：内核纯 Kotlin 编写，零 Compose / UI 依赖，体积仅数百 KB，毫秒级冷启动，原生发布到 JVM / Android / iOS / Linux 嵌入式设备。
2. **能力容器化（Capability Decoupling）**：彻底解耦特定硬件依赖，采用动态类型化容器注入平台能力，让舵机、屏幕、传感器、无障碍自动化按需组装。
3. **全双工拟人交互（Full-Duplex Pipeline）**：从“一问一答”走向“可打断、带情绪、自发心跳”的自然感知循环。
4. **认知与记忆沉淀（Continuous Learning）**：兼容 `agentskills.io` 开放标准与 MCP 协议，支持情景记忆分层与自主经验沉淀，越用越懂用户。

### 1.4 四大典型产品形态规划

| 落地形态 | 典型载体 | 核心特征与交互方式 | 关键技术扩展 |
|---|---|---|---|
| **桌宠机器人** | 桌面实体、树莓派、Linux/ESP32 硬件 | 物理舵机/肢体摆动、小液晶屏表情、触摸/碰撞传感器响应、空闲时自主好奇心心跳 | 舵机控制、表情渲染、传感器事件流、自主心跳循环 |
| **智能家居中控** | 无头网关（Headless Linux/车机/微型主机） | 纯远场语音控制、全屋 IoT 设备原语操作、家庭多环境传感器事件联动决策 | Matter/MQTT 驱动、全双工回声消除、无头会话路由 |
| **情感陪伴软件** | 手机/桌面 3D 虚拟人、跨平台独立 App | 拟人八维心理状态机、长程情景自传记忆、主动关怀与情绪共鸣、语气词与伴随动作 | 情绪状态机、Theory of Mind 用户画像、动作代码映射 |
| **星环移动随身助手** | Android / iOS 原生应用 | 随身携带、无障碍跨应用自动化点击、手机文件与多模态识别、IM 渠道联动 | 手机无障碍控制器、悬浮球常驻、离线语音模型 |

### 1.5 核心设计原则
1. **微内核原则（Microkernel）**：内核只负责循环、事件分发与扩展编排，严禁侵入具体业务逻辑。
2. **无头化优先（Headless First）**：所有核心状态均采用响应式 `Flow` / `StateFlow`，绝不在底层使用 Compose 快照状态。
3. **确定性与可见性**：高危与具身物理动作必须可审计、可中断，遵循安全护栏。
4. **模型自由（Model Agnostic）**：全面适配 OpenAI、Anthropic 兼容协议以及 DeepSeek、通义千问等主流服务商，支持端侧离线模型。

## 2. 行业背景与前沿生态对标

### 2.1 范式演进：从聊天框到具身与环境智能
当前 AI 正在经历第二波浪潮：从云端单一的“大模型问答”，走向与物理世界交互的“具身实体（Embodied AI）”与“环境智能（Ambient Intelligence）”。用户对机器人的诉求不再是冷冰冰的问答，而是像活物一样有小脾气、能感知触摸、能打断对话并真正控制实体设备。

### 2.2 前沿标杆生态拆解与启示

| 标杆项目 | 技术特色 | 优势与局限 | StarAgent 的汲取与定位 |
|---|---|---|---|
| **JetBrains Koog** | 官方 Kotlin Agent 框架 | 优点：纯 KMP、Ktor 插件体系。<br>局限：偏向企业端与后端，移动与物理硬件封装弱。 | **对齐其 KMP 与 Feature 插件哲学**，共享 KMP 生态。 |
| **LiveKit Agents / Pipecat** | 实时音视频与语音流水线 | 优点：极成熟的 WebRTC 全双工语音与打断机制。<br>局限：重度绑定 Python/C++ 及云端流媒体服务。 | **吸收其 Frame Pipeline 思想**，在 KMP 上构建端侧全双工打断管线。 |
| **Inworld AI / Honcho** | 虚拟人心理状态机与认知画像 | 优点：八维情绪向量、自发目标动机驱动、心理学用户画像。<br>局限：商业闭源，API 计费昂贵。 | **自研轻量级情绪数学模型与情景记忆系统**，集成进 Prompt 贡献层。 |
| **OpenClaw** | 跨平台开源个人助理 | 优点：Gateway + Node 拓扑，手机作为能力节点。<br>局限：单机 Gateway 较重，ClawHub 插件曾遭遇严重供应链投毒。 | **吸收其能力节点解耦概念，加强安全沙箱与总是确认门禁**。 |
| **小智 AI (ESP32)** | 国内开源硬件生态爆款 | 优点：低成本极客硬件生态极其活跃。<br>局限：端侧固件极其脆弱，缺乏本地长程记忆与通用工具编排。 | **StarAgent 作为高级大脑 SDK**，未来可直接作为小智类硬件的本地网关。 |

### 2.3 StarAgent 的核心护城河
1. **纯 Kotlin Multiplatform 原生底座**：打破“云端纯 Python”与“单片机 C 语言”的断层，一套语言从服务端、桌面端一直覆盖到手机与嵌入式 Linux 设备；
2. **端云混合混合闭环**：离线语音（sherpa-onnx）、端侧硬件加密（KeyStore）与云端高智商模型无缝融合；
3. **开放标准生态兼容**：首发完整支持 `agentskills.io` 与 `MCP (Model Context Protocol)` 协议。

## 3. 范围边界与职责划分

为防止系统膨胀失控，StarAgent 制定清晰的架构三界划分：

```
┌────────────────────────────────────────────────────────┐
│           Form Factors (产品形态层 - 各自独立发布)        │
│  StarAgent App │ Desktop Pet App │ SmartHome Daemon   │
└───────────────────────────┬────────────────────────────┘
                            │ 装配
┌───────────────────────────▼────────────────────────────┐
│         Capability Extensions (外围积木扩展库)          │
│  ext-motor │ ext-audio-duplex │ ext-emotion │ ext-device│
└───────────────────────────┬────────────────────────────┘
                            │ 依赖注入
┌───────────────────────────▼────────────────────────────┐
│            StarAgent Core SDK (通用无头内核)            │
│  agent-runtime │ agent-core │ agent-llm │ agent-tools  │
└────────────────────────────────────────────────────────┘
```

### 3.1 内核 SDK 职责（Core In-Scope）
- 驱动多步推理与行动的通用编排器（`TurnRunner`、`AgentLoop`）；
- 结构化事件流分发（`Flow<TurnEvent>`）；
- 核心模型抽象（`AgentDefinition`、`LlmTurn`、`Tool`、`ToolRegistry`）；
- 标准扩展接口（`AgentExtension` SPI）；
- 上下文与类型化能力容器（`CapabilityContainer`）；
- 多模型协议适配（OpenAI、Anthropic、流式解析与 SSE 解码）。

### 3.2 外围扩展职责（Extensions In-Scope）
- **具身硬件扩展**：舵机通信协议、屏幕表情渲染驱动、蓝牙/串口适配器；
- **语音管线扩展**：KWS 唤醒词、AEC 回声消除、VAD 断句、流式 TTS；
- **认知系统扩展**：`MemoryExtension`、`SkillExtension`、`EmotionStateMachine`；
- **设备控制扩展**：Android Accessibility 屏幕自动化、桌面命令行、系统通知；
- **智能家居扩展**：MQTT 客户端、Home Assistant 实体映射。

### 3.3 产品形态职责（Form Factors In-Scope）
- 负责具体的 UI/UE 展示（Compose Multiplatform 或无头守护进程）；
- 负责组装当前形态所需的具体扩展与硬件适配器；
- 负责最终产品的应用打包、分发与应用级生命周期管理。

### 3.4 严格排除项（Out of Scope）
- **禁止在 Core SDK 中包含图形库**（包括 Compose、Java AWT/Swing 等）；
- **禁止在 Core SDK 中编写特定传感器协议或芯片驱动代码**；
- **禁止将单一形态的业务状态管理（如手机聊天气泡维护）沉入底层**。

### 4.2 动态能力容器设计（IoC Capability Container）
淘汰原硬编码 12 个固定成员的 `ToolHost`，重构为基于类型安全的动态容器：

```kotlin
// 纯解耦的能力容器
class CapabilityContainer {
    private val capabilities = mutableMapOf<KClass<*>, Any>()

    fun <T : Any> register(type: KClass<T>, instance: T) {
        capabilities[type] = instance
    }

    @Suppress("UNCHECKED_CAST")
    fun <T : Any> get(type: KClass<T>): T? = capabilities[type] as? T

    inline fun <reified T : Any> get(): T? = get(T::class)
    inline fun <reified T : Any> require(): T = get(T::class) ?: error("Capability ${T::class.simpleName} missing")
}
```
* **效果**：机器人扩展只需注册 `MotorPort`，移动端扩展只需注册 `AccessibilityPort`。工具在调用时按需获取依赖，底座对具体硬件零知晓。

## 5. 核心能力与扩展体系

### 5.1 认知与长程记忆系统
1. **语义事实记忆（Semantic）**：用户静态事实（偏好、关系、禁忌），采用结构化提取与受外部网页污染闸门保护。
2. **情景自传记忆（Episodic）**：按时间轴沉淀的事件轨迹（“某天与主人共同解决了什么难题”），支撑长周期羁绊建立。
3. **拟人心理状态机（Emotion State Machine）**：
   - 包含三维连续情绪空间：`Valence`（正负情绪值）、`Arousal`（唤醒/精力程度）、`Dominance`（支配度）；
   - 伴随系统提示注入实时心智状态：“你现在觉得很疲倦但很开心，说话语气带着轻微的撒娇”。

### 5.2 技能与开放扩展生态
- **标准对齐**：完全遵循 `agentskills.io` 规范，SKILL.md 声明式元数据 + Markdown 指令；
- **三层渐进披露**：
  - Level 1: 技能目录注入 System Prompt（名字 + 简述，每条 ≤200 字，token 成本几乎恒定）；
  - Level 2: 模型命中时通过 `use_skill` 按需加载完整正文；
  - Level 3: 附带参考资料通过 `read_skill_file` 按需延迟读取；
- **自主经验固化**：提供受限的 `create_skill` 工具，允许 Agent 识别到重复经验时向用户提出固化建议，用户同意后写入。

### 5.3 全双工拟人语音管线（Audio Pipeline）
- **流式分句与快速打断**：TTS 合成与 PCM 播放采用双 Channel 有界缓冲，支持毫秒级清空队列与静音切断；
- **回声消除（AEC）与唤醒词（KWS）解耦**：硬件端音频流支持持续推流监听，在机器人自身发声时保持环境监听。

## 6. 安全、隐私与执行护栏

作为可能接触真实设备、电机舵机与私人生活的 Agent 底座，安全是生死线：

1. **凭据硬件隔离（Hardware KeyStore）**：
   所有模型 API Key、语音凭证统一由底层系统硬件安全区（AndroidKeyStore / TEE / 硬件加密存储）管理，落盘密文保护，禁用任何系统云备份提取。
2. **三级权限控制与 AlwaysConfirm 机制**：
   - **只读操作**（查看日历、读屏检查、搜索）：直接放行；
   - **常规操作**（发消息、记便签）：跟随全局 `ExecutionPolicy`（Auto / OnDemand）；
   - **高危与不可逆操作**（安装技能、固化代码、转账、删除、大角度物理动作）：声明 `alwaysConfirm = true`，**无视全局自动模式，必须经由人类明确确认**。
3. **外部输入污染拦截（Prompt Injection Defense）**：
   同轮内一旦抓取过外部不受信内容（网页、第三方邮件），整轮触发“受污染”保护，禁止向持久记忆落库，禁止自动创建/更新技能。

## 8. 典型落地形态与解决方案

### 8.1 形态 A：开源桌面陪伴机器人（StarAgent-Pet）
* **硬件方案**：香橙派/树莓派 Zero 2W + 2~3 个总线舵机（转头、仰头、耳朵动）+ 1.54寸圆形 LCD 液晶屏（眼球表情）+ 触摸感应外壳。
* **软件组装**：
  ```
  StarAgent-Pet Daemon
    ├── Core SDK (agent-runtime + agent-llm)
    ├── ext-motor (舵机动作序列播放器)
    ├── ext-expression (LCD 帧动画表情驱动)
    ├── ext-audio-duplex (带打断的离线+云端语音)
    ├── ext-emotion (萌宠小脾气心理引擎)
    └── ext-skills (桌面日常技能包)
  ```

### 8.2 形态 B：智能家居自主环境大脑（StarAgent-Home）
* **运行形态**：家庭软路由 / NAS / 智能音箱后台 Daemon（常驻内存仅数十 MB，无屏幕）。
* **软件组装**：
  ```
  StarAgent-Home Daemon
    ├── Core SDK (agent-runtime + agent-llm)
    ├── ext-homeassistant (通过 WebSocket 连接全屋 HA 实体)
    ├── ext-audio-duplex (远场麦克风阵列 + 唤醒词)
    ├── ext-tasks (离线定时任务调度中心)
    └── ext-im (微信/Telegram 远程报警与汇报通道)
  ```

## 10. 核心风险与应对策略

| 风险维度 | 具体风险表现 | 应对策略与设计保障 |
|---|---|---|
| **端侧算力与内存瓶颈** | 嵌入式硬件无法支撑大型模型或臃肿运行时 | 保持 Core SDK 微内核架构（<300KB），重型语音/视觉模型采用端云动态路由与按需装载 |
| **物理动作安全风险** | 模型幻觉导致舵机过度转动或夹伤用户 | 动作指令通过硬件驱动层物理限位护栏（Physical Boundary Guardrails）硬性阻断 |
| **长程对话记忆膨胀** | 对话积累数月导致上下文爆炸与费用失控 | 引入滑动窗口 + 自动后台压缩（Compaction Pipeline）与情景摘要提取 |
| **全双工网络抖动** | 云端语音延迟导致人机对话“抢话”或“发呆” | 采用本地 VAD + 毫秒级流式中断切片，确保打断反应时间 < 300ms |

## 附录 A：核心术语表

- **Agent Substrate（智能体底座）**：负责认知编排、上下文调度、工具执行与状态流转的基础引擎，与具体硬件外设和图形界面无关。
- **Capability Container（能力容器）**：采用控制反转（IoC）机制按类型动态注册与索取硬件能力的通用环境契约。
- **TurnRunner（单轮编排器）**：统一封装单次人机交互或自发事件驱动中“思考-工具-行动”闭环的核心调度器。
- **Full-Duplex Barge-in（全双工打断）**：机器人在说话或发声时持续监听环境，人类开口即刻静音切断的技术机制。
- **Emotion State Machine（情绪状态机）**：驱动智能体产生拟人心理变化与自发行为的动态向量数学模型。
