## 摘要

星环智能 Agent 是一款**运行在用户手机上的高自由度 AI Agent**。它的目标不是再做一个聊天窗口，而是让 AI 真正"住进"手机里——理解用户的意图，动手替用户操作手机上的应用，记住用户的偏好与历史，并随着使用不断自我进化。

与电脑端 Agent 相比，手机是用户数字生活的重心，也是目前 Agent 能力覆盖最薄弱的环节。星环智能 Agent 以移动端为第一现场，通过**长期记忆、自进化、Skill 生态、IM 渠道连接、模型自由接入**五大能力支柱，构建一个用户可以自由配置、自由扩展、自由掌控的私人智能体平台；在此基础上，二期进一步让 Agent 具备**真机操作**能力，真正代替用户使用手机。

产品分两期推进：**一期**先把"支持自定义大模型的、完善的 AI 智能体"做扎实，交付对话与多模态交互、记忆、任务托管、技能、渠道与模型自由；**二期**让 Agent 长出双手，能够真实操作用户手机。

一句话概括产品主张：**把手机交给一个会学习、能动手、听你安排的 Agent。**

## 1. 产品概述

### 1.1 一句话定义

星环智能 Agent 是一个定位于移动端的 AI Agent 工具，能力对齐电脑上的 Agent，但运行在用户随身携带的手机上，能真实地代替用户操作手机、完成任务。

### 1.2 产品定位

| 维度 | 定位 |
| --- | --- |
| 形态 | 移动端 App（自主可控的 Agent 运行时） |
| 类比 | "手机上的 Agent"，对标电脑端 Agent 的能力边界 |
| 交互 | 对话 + 语音 + 拍照，不止于打字 |
| 能力边界 | 不限于聊天：一期交付内容与信息劳动、任务托管；二期延伸至真机操作 |
| 开放程度 | 高自由度：智能体、任务、模型、Skill 均可由用户自定义 |
| 用户关系 | 长期陪伴型——有记忆、会进化，越用越懂用户 |

### 1.3 愿景

让每个人都能拥有一个**属于自己、听自己指挥、并且越用越聪明**的移动智能体——它不是一个被厂商定义好功能的产品，而是一个可以被用户塑造成任何样子的能力底座。

### 1.4 目标用户

**【待确认：以下为基于产品定位推导的画像，需结合真实调研收敛】**

1. **效率敏感的个人用户**——希望把手机上重复、繁琐的操作（打卡、签到、比价、抢票、整理相册、批量发消息）交给 Agent。
2. **数字生活重度用户**——手机上装了数十个 App，跨 App 的信息流转与操作成本高，需要"一句话跑通多个 App"的能力。
3. **开发者与极客玩家**——看重"自定义模型服务商 + 自定义智能体 + Skill 安装"的开放性，希望按自己的方式拼装 Agent。
4. **有自动化诉求的小微经营者/自由职业者**——需要定时任务、周期任务来托管日常运营动作（如定时发布、定时汇总）。

### 1.5 核心设计原则：高自由度

"高自由度"是贯穿全产品的第一性原则，具体体现为**四个可自定义**：

- **模型自由**：用户可自行配置大模型服务提供商，不被单一厂商锁定。
- **智能体自由**：支持自定义多种智能体，面向不同场景使用不同人格与能力组合。
- **任务自由**：支持自定义一次性任务、定时任务、周期任务。
- **能力自由**：可通过安装 Skill 持续扩展 Agent 的能力边界。

## 2. 行业背景与机会

### 2.1 从"能聊"到"能办"

AI 应用正在经历一次范式转移：第一阶段是**对话式助手**，解决"问答与生成"；第二阶段是 **Agent**，解决"理解意图并真实执行"。用户对 AI 的期待已经从"告诉我怎么做"变成"直接帮我做完"。

### 2.2 手机是 Agent 最大的未被占领场景

电脑端 Agent 已在浏览器操作、桌面自动化等方向快速成熟，但用户的数字生活重心早已迁移到手机：

- 大量高频事务（支付、社交、出行、健康、政务）**只在手机 App 上完成**，没有网页版可替代。
- 手机端 App 生态封闭，跨 App 操作是用户的真实痛点。
- 手机具备**麦克风、摄像头、传感器**等天然的多模态输入能力，是 Agent 感知用户语境的最佳载体。

### 2.3 机会窗口

移动端 Agent 目前仍处在早期：能力覆盖薄、开放性差、多数产品停留在"聊天框 + 少量插件"。谁能率先做到**真机操作 + 长期记忆 + 开放生态**三者的结合，谁就有机会定义移动端 Agent 的标准形态。

## 3. 产品总体架构

产品能力可以划分为四层，自下而上构成完整闭环：

```
┌─────────────────────────────────────────────┐
│  交互层   对话 · 语音 · 拍照识别 · IM 渠道      │
├─────────────────────────────────────────────┤
│  编排层   智能体 · 任务（一次性/定时/周期）      │
├─────────────────────────────────────────────┤
│  能力层   真机操作 · Skill 生态 · 记忆 · 自进化  │
├─────────────────────────────────────────────┤
│  模型层   自定义大模型服务商（多模型可插拔）      │
└─────────────────────────────────────────────┘
```

**四种交互入口**（对话 / 语音 / 拍照 / IM）对接**同一个 Agent 内核**，保证能力一致、记忆共享；**编排层**决定"谁来干、什么时候干"；**能力层**决定"能不能干、干得好不好"；**模型层**提供底层智能并可被用户替换。

## 4. 核心能力体系

> **分期提示**：本章 4.1 真机操作为**二期目标**，一期不交付，作为能力蓝图保留；其余能力均为一期范围。

### 4.1 真机操作能力（Agent 的"手"）· 二期目标

> **分期说明**：真机操作作为**二期目标**，一期不交付。但它是产品长期差异化的根，因此保留在本章作为能力蓝图；一期在交互上通过"任务托管 + 产物沉淀"来补位，详见[《一期交互形态设计》](02-一期交互形态设计.md)。

这是本产品区别于普通聊天助手的根本能力。

- **能力描述**：Agent 能真实地在用户手机上执行操作，代替用户点击、输入、切换应用、完成事务流程，而非仅仅给出操作建议。
- **与"聊天"的关系**：聊天是交互方式，操作是交付结果。产品承诺的是后者。
- **价值**：用户从"我来操作"变为"我描述目标"。
- **关键约束【待确认】**：具体实现路径（无障碍服务 / 自动化框架 / 系统级权限）、支持的 App 范围、能否在锁屏或后台执行、失败回退与人工接管机制。

> 建议在白皮书中明确一句边界承诺：**Agent 的每一步操作对用户可见、可中断、可追溯。** 这是移动端操作类能力的信任基础。

### 4.2 记忆系统（Agent 的"脑"）

- **能力描述**：Agent 具备记忆能力，能够积累并调用与用户相关的信息，使交互具备连续性。
- **价值**：解决"每次都要重新解释一遍"的体验断裂，让 Agent 从工具变成"认识你的人"。
- **记忆层次【待确认：建议按此分层落地】**
  - 会话记忆：单次任务内的上下文；
  - 长期记忆：用户偏好、习惯、常用流程；
  - 任务记忆：历史任务的执行轨迹与结果，用于复用与优化。
- **用户控制权**：记忆必须可查看、可编辑、可删除——这是隐私合规的底线，也是"高自由度"的应有之义。

### 4.3 自进化（Agent 的"成长"）

- **能力描述**：Agent 在使用过程中自我进化，能力随使用时间增长而增强。
- **落地方式【待确认：建议明确自进化的具体机制，避免成为空泛概念】**
  - 从历史执行轨迹中沉淀经验，自动形成可复用的能力（对应 Skill）；
  - 根据用户反馈与纠正，持续优化执行策略与偏好模型；
  - 在记忆更新与 Skill 迭代层面进化，**而非重新训练模型权重**。
- **价值**：产品从"出厂即定型"变为"越用越好用"，形成使用时长与产品价值的正相关，天然提升留存。

### 4.4 Skill 生态（Agent 的"技能包"）

- **能力描述**：支持安装 Skill，持续扩展 Agent 的能力范围。
- **形态**：Skill 是可插拔的能力单元，一个 Skill 封装一类具体事务的处理方式。
- **三个来源**：官方提供、社区/第三方贡献、Agent 在执行中自发生成。
- **价值**：能力扩展不再依赖 App 版本迭代，打开生态天花板。
- **生态设计要点【待确认】**：Skill 的描述规范、权限模型、分发机制、质量与安全审核标准、开发者激励机制。

### 4.5 多模态交互（Agent 的"感官"）

产品支持超出文本的输入方式，适配移动端的使用姿势：

| 模态 | 能力 | 说明 |
| --- | --- | --- |
| 对话 | 文本交互 | 基础入口，能力完整 |
| 语音 | 语音交互 | 移动场景下最自然的输入方式，解放双手 |
| 拍照 | 拍照识别 | 通过外接大模型实现视觉理解，让 Agent "看得见"现实世界 |

**拍照识别的实现方式**：通过接入外部大模型服务完成图像理解，而非依赖端侧模型。这一选择与"模型自由"的产品主张一致——**视觉能力同样可以由用户自行选择服务商**，产品本身不绑定特定模型。

### 4.6 IM 渠道连接（Agent 的"触点"）

- **能力描述**：Agent 可连接 IM 渠道，让用户在自己常用的聊天工具里直接调用 Agent。
- **价值**：
  - 用户无需打开特定 App，在已有聊天场景中即可下发任务、接收结果与通知；
  - Agent 从"一个 App"变为"一个随时可召唤的联系人"；
  - 任务执行结果可以主动推送到用户身边，尤其适配定时/周期任务的交付。
- **【待确认】**：首批支持的 IM 渠道清单、账号绑定方式、消息安全与合规策略。

### 4.7 模型自由：自定义大模型服务商（Agent 的"引擎"）

- **能力描述**：支持用户自定义大模型服务提供商，不锁定单一模型厂商。
- **价值**：
  - **成本可控**：用户可根据任务量级与预算自行选择模型；
  - **能力择优**：不同任务匹配不同模型（如视觉任务用视觉模型、推理任务用推理模型）；
  - **数据与合规自主**：对数据敏感的用户可接入私有化或自建模型服务；
  - **不惧模型迭代**：新模型出现时可即时接入，产品能力随生态水涨船高。
- **接入方式（已确定）**：内置主流服务商，并支持用户**自定义服务商**——自定义时在
  **OpenAI 兼容**与 **Anthropic** 两种协议之间二选一，接口地址、模型清单、API Key 全部由用户填。
  模型清单支持直接从服务商拉取，不需要用户手打模型名。
- **【待确认】**：默认配置与开箱体验之间的平衡（是否为非技术用户提供官方托管通道）、
  以及模型能力的差异化路由（不同任务自动匹配不同模型）。

> **关联**：开箱体验与默认通道的设计见[《一期交互形态设计》](02-一期交互形态设计.md)第 4.6 节，那是本产品最容易被低估的风险点。

### 4.8 智能体与任务系统（Agent 的"分工与日程"）

**自定义智能体**：用户可以定义多个智能体，每个智能体面向不同场景、承担不同角色、具备不同能力组合。

**自定义任务**：任务是用户对 Agent 下达的、可托管执行的工作单元，支持三种形态：

| 任务类型 | 触发方式 | 典型用途 |
| --- | --- | --- |
| 一次性任务 | 立即或指定时刻执行一次 | 临时性事务处理 |
| 定时任务 | 在指定时间点执行 | 每日签到、定点提醒与执行 |
| 周期任务 | 按固定周期重复执行 | 周期性汇总、定期维护类操作 |

- **价值**：Agent 从"被动响应"升级为"主动托管"。用户交代一次，Agent 长期负责——这是从工具到助手的质变。
- **【待确认】**：任务失败重试策略、执行条件（网络/电量/解锁状态）、任务间依赖编排。

> **关联**：任务的创建交互设计见[《一期交互形态设计》](02-一期交互形态设计.md)第 4.3 节"对话即任务创建"。

## 5. 技术架构

### 5.1 客户端技术选型

项目采用 **Kotlin Multiplatform（KMP）+ Compose Multiplatform** 技术栈，一套核心代码同时支撑 **Android、iOS、Desktop** 三端（工程结构见 `StarAgentApp/StarAgent`：`androidApp` / `iosApp` / `desktopApp` / `shared`）。

**选型理由**：

- **共享 Agent 内核**：交互逻辑、记忆、任务编排等核心能力在 `shared` 模块统一实现，三端行为一致，避免重复开发；
- **原生能力可达**：真机操作、语音、拍照等强平台相关能力通过 `expect/actual` 机制分别落地，既共享又不受限；
- **多端协同想象空间**：Desktop 端的保留为未来"手机 Agent 与电脑 Agent 协同"埋下伏笔；
- **工程效率**：单一技术栈维护三端，长期人力成本显著低于原生分别开发。

### 5.2 分层职责

| 层级 | 职责 | 关键考量 |
| --- | --- | --- |
| 交互层 | 对话、语音、拍照、IM 渠道接入 | 多入口体验一致，记忆共享 |
| 编排层 | 智能体路由、任务调度与生命周期 | 可靠性、可观测性、失败可恢复 |
| 能力层 | 真机操作、Skill 运行时、记忆、自进化 | 权限最小化、操作可追溯 |
| 模型层 | 多模型服务商适配与路由 | 统一抽象接口，屏蔽厂商差异 |

### 5.3 关键技术挑战

1. **跨应用操作的稳定性**——不同 App 界面结构差异大、版本迭代频繁，需要具备界面理解与自适应能力。
2. **端云协同的时延与成本**——真机操作需本地实时响应，复杂推理走云端模型，需要合理的任务切分。
3. **记忆的存储与检索**——长期记忆的写入、去重、召回与隐私保护需要系统性设计。
4. **多模型适配的工程成本**——不同厂商协议、鉴权、能力差异需要统一抽象层消化。

## 6. 典型应用场景

## 7. 差异化竞争力

| 对比维度 | 普通聊天助手 | 插件化助手 | **星环智能 Agent** |
| --- | --- | --- | --- |
| 交付结果 | 只给建议 | 有限功能内执行 | **真机操作，真实完成** |
| 记忆 | 会话内短期 | 弱 | **长期记忆，越用越懂你** |
| 成长性 | 出厂即定型 | 依赖版本更新 | **自进化 + Skill 安装** |
| 模型 | 厂商锁定 | 厂商锁定 | **用户自定义服务商** |
| 自动化 | 无 | 有限 | **一次性 / 定时 / 周期任务** |
| 交互 | 文本 | 文本 | **对话 + 语音 + 拍照 + IM** |
| 可定义性 | 不可定义 | 少量配置 | **智能体、任务、能力全面自定义** |

**核心差异一句话**：别人在手机里放了一个"会聊天的 AI"，星环智能 Agent 在手机里放了一个"会干活的、听你安排的、越用越聪明的智能体"。

> **分期提示**："真机操作"一行为二期能力。一期的差异化主要来自**模型自由 + 记忆 + 任务托管 + 多渠道**，详见[《一期交互形态设计》](02-一期交互形态设计.md)。

## 8. 安全、隐私与合规

移动端 Agent 拥有较高的系统权限与用户数据访问能力，安全与隐私是产品能否成立的前提，而非附加项。

**【待确认：本章为框架建议，需由法务与安全团队共同细化】**

1. **操作可控**：Agent 的每一步操作对用户可见，支持随时中断、回滚与审计追溯。
2. **权限最小化**：仅在必要时申请必要权限，并向用户清晰说明用途。
3. **敏感操作确认**：涉及支付、转账、删除、对外发送等不可逆动作，必须要求用户显式确认。
4. **数据边界**：明确哪些数据留在端侧、哪些会发送至模型服务商；用户自定义模型服务商时，应明确告知数据流向由其选择的服务商决定。
5. **记忆可管理**：用户可查看、编辑、导出、删除 Agent 的全部记忆。
6. **合规适配**：遵循个人信息保护相关法规，落实用户授权、数据最小化与可撤回机制。

## 9. 产品路线规划

**【待确认：以下为能力递进逻辑建议，具体版本划分与时间点需与研发排期对齐】**

**分期原则**：**真机操作作为二期目标**。一期先把"支持自定义大模型的、完善的 AI 智能体"做扎实——即把交互、记忆、任务、技能、渠道、模型自由这几件事做完整，再让 Agent 长出"手"。

| 阶段 | 目标 | 核心能力 |
| --- | --- | --- |
| **一期：成为完善的智能体** | 把 Agent 的"脑"和"嘴"做透 | 对话与多模态交互、长期记忆、自定义模型服务商、自定义智能体、一次性/定时/周期任务、Skill 安装、IM 渠道连接、自进化 |
| **二期：长出双手** | Agent 能真实操作用户手机 | 真机操作（跨应用执行）、操作可视化与可中断、敏感动作确认、任务与真机执行打通 |
| **三期：生态化** | 从产品走向平台 | Skill 开放生态、第三方贡献与分发、多端协同（手机 Agent 与电脑 Agent 协作） |

> 一期的详细交互设计见[《星环智能 Agent 一期产品交互形态设计》](02-一期交互形态设计.md)。

## 10. 商业模式

**【待确认：本章为待决策项，需结合成本结构与用户付费意愿调研确定】**

可考虑的路径：

1. **免费 + 增值订阅**：基础 Agent 能力免费，高级能力（更多定时任务、更长记忆、更多智能体）订阅解锁。
2. **模型用量分成 / 转售**：默认模型通道按用量计费，用户也可自带 API Key 自行接入。
3. **Skill 生态分成**：第三方付费 Skill 上架，平台抽取分成。
4. **企业版**：面向小微经营者提供批量设备管理、私有化模型接入与合规审计能力。

> **成本提示**：本产品的单位用户成本与大模型调用量强相关，商业模式设计需与"模型自由"带来的成本弹性协同考虑。

## 11. 风险与挑战

| 风险类别 | 具体风险 | 应对方向 |
| --- | --- | --- |
| 平台风险 | 系统对自动化操作/无障碍权限的限制趋严 | 多路径实现方案，保持合规表达 |
| 技术风险 | 跨 App 操作在界面迭代后失效 | 提升界面理解的泛化能力，建立失效监控与快速修复 |
| 成本风险 | 模型调用成本随用户活跃度攀升 | 模型自由带来成本弹性；端云任务合理切分 |
| 信任风险 | 用户不敢把手机交给 Agent 操作 | 操作可见可中断、敏感动作二次确认 |
| 合规风险 | 记忆与数据涉及个人信息保护 | 记忆可管理、数据流向透明、授权可撤回 |
| 概念风险 | "自进化"若无具体机制支撑易被视为营销话术 | 明确落到记忆更新与 Skill 沉淀，可验证、可展示 |

> **一期特别提示**：表中「平台风险 / 技术风险 / 信任风险」均与真机操作相关，属二期风险。一期的头号风险是**模型配置漏斗**，详见[《一期交互形态设计》](02-一期交互形态设计.md)第 7 章。
