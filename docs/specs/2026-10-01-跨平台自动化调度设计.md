## 0. 背景与目标

### 0.1 现状与痛点

StarAgent 目前具备了完整的任务 CRUD 工具体系与 `AgentLoop` 工具执行循环，但定时任务的触发依然依赖**应用前台的 30 秒心跳协程**（`shared/src/commonMain/.../App.kt:87`）：
- **退到后台失效**：手机锁屏或退回桌面后，进程被系统挂起（Doze / 冻结），30 秒心跳停止，到点任务无法触发；
- **进程被杀失效**：应用退出或被系统回收后，任务完全无法执行；
- **电脑端息屏/最小化**：桌面端窗口关闭或睡眠后无法唤醒。

这导致"任务托管"目前只能在"用户一直开着 App 看着它"时工作，失去了托管的本质意义。

### 0.2 目标

构建跨平台系统级任务调度子系统（`automations`），全面覆盖 **Android / Desktop (JVM) / iOS**：
1. **系统级定时唤醒**：在 App 退后台、锁屏甚至进程杀死后，由操作系统准时唤醒执行；
2. **最近优先动态单点排期**：应用层向操作系统只预约**距离当前最近的单一唤醒时刻**，极致降低功耗与系统资源开销；
3. **任务结果系统通知送达**：后台执行完毕后，通过跨平台系统通知（Android 状态栏 / 桌面原生托盘通知 / iOS 本地推送）主动将结论预览推送给用户。

## 1. 总体架构与跨平台分层

遵循 StarAgent 既有的架构规范（`core:platform` 定义契约与注册表、`core:data` 管理中枢业务、`core:bootstrap` 分端装配）：

```
                     ┌──────────────────────────────┐
                     │          core:data           │
                     │  (AppState 动态计算最近执行时刻  │
                     │   + runDueTasksAndNotify)    │
                     └──────────────┬───────────────┘
                                    │ 调用
                                    ▼
                     ┌──────────────────────────────┐
                     │        core:platform         │
                     │  TaskSchedulers / Notifiers  │
```

## 2. 核心契约与抽象设计（`core:platform`）

### 2.1 任务调度契约（`schedule/TaskScheduler.kt`）

```kotlin
package com.starringbox.staragent.core.platform.schedule

/**
 * 跨平台系统级任务调度器。
 */
interface TaskScheduler {
    /**
     * 向操作系统预约下一次系统唤醒时刻（epoch 毫秒）。
     * [triggerAtMillis] 为 null 时表示当前没有待执行的活跃任务，清除操作系统的唤醒预约。
     */
    fun scheduleNextWakeup(triggerAtMillis: Long?)
}

/** 没装实现时的默认兜底（Noop） */
private object NoopTaskScheduler : TaskScheduler {
    override fun scheduleNextWakeup(triggerAtMillis: Long?) = Unit
}

/**
 * 调度器静态注册表。与 LocalStores、MediaPickers 同构。
 */
object TaskSchedulers {
    private var installed: TaskScheduler = NoopTaskScheduler

    fun install(scheduler: TaskScheduler) {
        installed = scheduler
    }

    val current: TaskScheduler get() = installed
    val available: Boolean get() = installed !== NoopTaskScheduler
}
```

### 2.2 唤醒回调解耦（`schedule/WakeupTrigger.kt`）

为了杜绝 `core:platform` 反向依赖 `core:data` 或 `AppState`，平台层与数据层通过轻量的函数式句柄解耦：

```kotlin
package com.starringbox.staragent.core.platform.schedule

/**
 * 系统唤醒反向触发器。
 *
 * 操作系统在后台唤醒广播/线程/后台任务时，直接调用 [fire]；
 * [AppState] 在构造时向其注册自己的执行函数。
 */
object WakeupTrigger {
    private var handler: (suspend () -> Unit)? = null

    fun registerHandler(action: suspend () -> Unit) {
        handler = action
    }

    suspend fun fire() {
        handler?.invoke()
    }
}
```

### 2.3 系统通知契约（`notify/Notifier.kt`）

```kotlin
package com.starringbox.staragent.core.platform.notify

interface Notifier {
    /**
     * 向系统通知中心发送一条本地通知。
     * [id] 为去重与更新标识；[title] 标题；[content] 摘要文本。
     */
    fun notify(id: String, title: String, content: String)
}

private object NoopNotifier : Notifier {
    override fun notify(id: String, title: String, content: String) = Unit
}

object Notifiers {
    private var installed: Notifier = NoopNotifier

    fun install(notifier: Notifier) {
        installed = notifier
    }

    val current: Notifier get() = installed
    val available: Boolean get() = installed !== NoopNotifier
}
```

## 3. 动态单点排期中枢（`core:data`）

### 3.1 最近优先（Earliest-First）算法

`AppState` 不需要维护多个系统定时器，只需找到当前所有活跃任务中最早要跑的一个：

```kotlin
internal fun nextSystemWakeupMillis(): Long? {
    val boundary = now().toEpochMilliseconds()
    return tasks
        .filter { it.status == TaskStatus.Active }
        .mapNotNull { it.nextRunAt }
        .filter { it > boundary }
        .minOrNull()
}

fun syncNextSystemWakeup() {
    TaskSchedulers.current.scheduleNextWakeup(nextSystemWakeupMillis())
}
```

### 3.2 触发同步的时机

在且仅在以下 4 个事件发生时触发 `syncNextSystemWakeup()`：
1. **冷启动加载完成时**（`init` / `restoreSettings` 末尾）；
2. **新建任务落库时**（`createTaskFromTool` / `confirmDraft`）；
3. **修改任务时间时**（`updateTaskFromTool`）；
4. **任务执行完毕计算出下一期时刻时**（`reschedule`）。

### 3.3 后台执行与通知发送（`runDueTasksAndNotify`）

```kotlin
suspend fun runDueTasksAndNotify() {
    runDueTasks()
    syncNextSystemWakeup()
}
```
并在 `runTask` 成功执行后，调用：
```kotlin
Notifiers.current.notify(
    id = task.id,
    title = "定时任务「${task.title}」已完成",
    content = raw.take(120).trim(),
)
```

## 4. 三端平台实现细节

### 4.1 Android 端实现

1. **`AndroidTaskScheduler`**：
   - 依赖系统 `AlarmManager`；
   - 对 `triggerAtMillis != null`：
     ```kotlin
     val intent = Intent(context, TaskAlarmReceiver::class.java)
     val pendingIntent = PendingIntent.getBroadcast(
         context, 0, intent,
         PendingIntent.FLAG_UPDATE_CURRENT or PendingIntent.FLAG_IMMUTABLE
     )
     if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.M) {
         alarmManager.setExactAndAllowWhileIdle(AlarmManager.RTC_WAKEUP, triggerAtMillis, pendingIntent)
     } else {
         alarmManager.setExact(AlarmManager.RTC_WAKEUP, triggerAtMillis, pendingIntent)
     }
     ```
   - 对 `triggerAtMillis == null`：`alarmManager.cancel(pendingIntent)`。

2. **广播接收器 `TaskAlarmReceiver`**：
   - 继承 `BroadcastReceiver`，在 `onReceive` 中使用 `goAsync()` 开启挂起协程：
     ```kotlin
     val pendingResult = goAsync()
     CoroutineScope(Dispatchers.Default).launch {
         try {
             WakeupTrigger.fire()
         } finally {
             pendingResult.finish()
         }
     }
     ```
   - 注册 `BootReceiver` 监听 `ACTION_BOOT_COMPLETED`：设备重启后触发 `WakeupTrigger.fire()`，恢复排期。

3. **`AndroidNotifier`**：
   - 初始化创建通知渠道 `NotificationChannel("staragent_tasks", "任务通知", IMPORTANCE_DEFAULT)`；
   - 使用 `NotificationCompat.Builder` 发送带应用图标的标准通知，点击跳转 `MainActivity`。

### 4.2 Desktop (JVM) 端实现

1. **`DesktopTaskScheduler`**：
   - 使用单线程守护线程池：`Executors.newSingleThreadScheduledExecutor { Thread(it).apply { isDaemon = true; name = "staragent-scheduler" } }`；
   - 调度逻辑：
     ```kotlin
     currentFuture?.cancel(false)
     if (triggerAtMillis == null) return
     val delay = maxOf(0L, triggerAtMillis - System.currentTimeMillis())
     currentFuture = executor.schedule({
         runBlocking { WakeupTrigger.fire() }
     }, delay, TimeUnit.MILLISECONDS)
     ```

2. **`DesktopNotifier`**：
   - 基于 `java.awt.SystemTray.isSupported()`：
     - 若支持系统托盘，构建托盘图标并通过 `trayIcon.displayMessage(title, content, MessageType.INFO)` 弹出气泡；
     - 若无图形托盘（如纯终端/无头测试），静默忽略，保证不崩溃。

### 4.3 iOS 端实现

1. **`IosTaskScheduler`**：
   - 基于 iOS BackgroundTasks 框架，使用 `BGTaskScheduler.sharedScheduler` 提交 `BGAppRefreshTaskRequest`；
   - 设定 `earliestBeginDate = NSDate(timeIntervalSince1970 = triggerAtMillis / 1000)`。

2. **`IosNotifier`**：
   - 基于 `UNUserNotificationCenter.currentNotificationCenter()` 发送本地通知。

## 5. 错误处理与容错机制

1. **Doze / 锁屏节电兼容**：Android 端使用 `setExactAndAllowWhileIdle` 保证在系统节电模式下仍能唤醒；
2. **设备重启自愈**：通过 `BOOT_COMPLETED` 广播，重启后自动拉起检查并向系统注册下一次 Alarm；
3. **过期待执行兜底**：如果设备长时间关机、开机后发现时间戳已过期，`AppState.scheduleUnplanned()` 能够平滑排到下一个合法周期，避免集中倾泻执行；
4. **无托盘桌面环境**：`DesktopNotifier` 判定 `SystemTray.isSupported()` 为 false 时安全回退，不抛出 AWT 异常。

## 6. 测试策略

遵循严谨的 TDD 测试策略：

1. **`core:platform` 单测（`TaskSchedulerRegistryTest`）**：
   - 验证 `TaskSchedulers` 注册与默认 Noop 行为；
   - 验证 `WakeupTrigger` 的回调注册与 `fire()` 正常执行。
2. **`core:data` 动态最近排期算法单测（`TaskSchedulerSyncTest`）**：
   - 多个不同时间任务并存时，验证 `nextSystemWakeupMillis()` 正好返回最早的那个；
   - 验证全部暂停时返回 `null`；
   - 验证任务执行完成重排期后，下一个时间戳正确刷新。
3. **通知发送单测（`TaskNotificationTest`）**：
   - 验证任务成功执行后，调用了 `Notifier.notify`，且内容为执行结论前 120 字摘要。
4. **Desktop 调度器单测（`DesktopTaskSchedulerTest`）**：
   - 注入时间戳，验证延迟计算与回调唤醒。
