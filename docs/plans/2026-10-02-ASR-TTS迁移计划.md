# AiFaceTech → StarAgent：ASR / TTS 迁移计划

日期：2026-10-02。本文基于本地源码盘点，尚未实施或运行编译、设备测试。

源码根目录：

- 源：`../AiFaceTech/HappyFaceAi`（相对 StarAgent 仓库根），HEAD `e616743`。
- 目标：`StarAgentApp/StarAgent`，HEAD `b942e48`；盘点包含当前工作区内容。
- 目标已有未提交修改：`AgentLoop.kt`、`AndroidAccessibilityController.kt`、`AndroidDeviceOperationService.kt`。实施前核对差异，保留现有工作。

## 1. 结论与范围

采取“复用语音算法与协议，适配 StarAgent 的状态、平台装配和会话生命周期”。两边都是 Kotlin Multiplatform，适合源码迁移；不应将源项目三个语音库连同存储、网络、机器人业务全部导入。

用户确认后的执行顺序：P0 → P3 离线能力 → P1 云端基础 → P2 流式播报 → P4 平台验收。优先 Android / Windows Desktop，iOS 单独安排 Mac/真机验收，不能以 commonMain 编译代替 iOS 可用性验证。

| 能力 | StarAgent 当前源码 | AiFaceTech 可迁移部分 | 处理 |
| --- | --- | --- | --- |
| 按住说话、整段录音、WAV 播放 | 已有 | 重复能力 | 保留目标实现与交互 |
| 云 ASR / TTS | OpenAI 风格、火山 Agent Plan | MiMo ASR / TTS | 新增独立协议实现，保留旧服务商 |
| 回复朗读 | 回复完成后合成、播放整段 | 断句、音频流、顺序播放、有界队列 | 分两步接入：先音频流，后文本流 |
| 离线 ASR / TTS | 有平台系统能力；未见 SenseVoice/Piper 接入 | SenseVoice、Piper | 独立阶段，隔离原生依赖 |
| 静音过滤 | 本地 WAV 能量判断，部分响应概率判断 | Silero VAD、语音段裁剪 | 随离线阶段引入，可回退现有规则 |
| iOS | 已写系统录播/识别合成实现，入口尚未装配 | 流式 PCM、离线引擎为不支持实现 | 基础接线复用目标；流式另行实现 |

基础交付范围是：语音转文字进入现有单聊/群聊、文字回复可朗读、配置可保存、取消与失败可正确收尾。流式和离线能力是后续明确的交付项；不随迁移引入机器人表情、口型、摄像头、唤醒词、常驻监听或实时双向对话。

## 2. 关键源码与必须适配的差异

源项目（以下路径相对 `HappyFaceAi`）：

- `lib_business/lib_asr/.../client/AsrClient.kt`：MiMo 实际走 `/chat/completions`、JSON 音频 data URI、`api-key` 鉴权。README 所写 multipart 与实码不符。迁移使用结构化 JSON 生成/解析，替换源文件的手拼 JSON、正则提取。
- `lib_business/lib_tts/.../client/TtsClient.kt`：整段 base64 音频及事件流音频；流式内置音色路径限定 `mimo-v2.5-tts`，输出 24 kHz 单声道 PCM16LE，处理跨事件的半个采样。
- `lib_business/lib_voice/.../SpeechSentenceBuffer.kt`、`SpokenReplyPipeline.kt`：首句/后续句切分、容量 2 的句子队列、容量 8 的音频队列、失败后继续保留文本。
- `lib_business/lib_voice/src/{androidMain,jvmSharedMain}/.../SpeechPcmPlayer*.kt`：平台流式播放；iOS 对应文件当前抛出不支持错误。
- `SenseVoiceAsr*`、`PiperTts*`、`SpeechCapture.kt`、`SpeechDetector*`：离线模型、下载校验与 VAD；需要替换源端 storage 和模型目录依赖。

目标项目（以下路径相对 `StarAgentApp/StarAgent`）：

- `core/platform/.../voice/Speech.kt`：`Transcriber.start/finish/cancel` 与 `Synthesizer.speak/stop` 是现有业务入口；继续兼容。
- `core/platform/.../voice/{Recorder,Player,Voice,Wav}.kt`：平台注册表与整段录播。WAV 封装默认 16 kHz，不能直接拿来封装 24 kHz TTS 音频。
- `core/llm/.../{ModelSpeech,VolcSpeech}.kt`：现有云协议。火山虽然走 WebSocket/事件流，目标实现仍是在录完后上传、收完整音频后播放。
- `core/model/.../SpeechProvider.kt`、`core/data/.../{AppState,SettingsStore,Seed}.kt`、`feature/settings/.../SpeechConfigScreen.kt`：配置入口。当前 ASR/TTS 共用一家服务商和 Key，ASR 模型必填；不能直接容纳独立选择的 Piper TTS。
- `feature/chat/.../{VoiceHold,ChatScreen,GroupChatScreen}.kt`：现有手势、发送、完成后朗读接线。流式启用后必须关闭同一回复的完成后重复朗读。
- `core/data/.../AgentLoop.kt`：`onText` 是非挂起回调且跨工具循环输出；不能直接接源流水线的挂起队列，必须定义每轮开始/结束、工具轮与最终回复的播报策略。

构建适配：源 Kotlin 2.4.20 / Ktor 3.5.0 / AGP 9.1.1，目标 Kotlin 2.4.10 / Ktor 3.5.2 / AGP 9.0.1。首轮沿用目标版本，逐项修正 API 与依赖；不复制源 version catalog 或顺带升级整个项目。

## 3. 目标职责分配

- `core:model`：语音配置、能力标记、音频格式等纯模型，不依赖平台/Compose。
- `core:platform` 的 voice 包：设备录音、权限、系统 ASR/TTS、整段及流式 PCM 播放。
- `core:llm`：第一阶段沿用既有语音协议位置，新增 `MiMoSpeech` 和可复用流式解码；使用目标 Ktor 引擎与错误处理，不引入源 `lib_network`。
- `core:data`：语音配置迁移、会话级 `SpeechSession`、断句与播报队列、停止和失败状态；界面只调用 AppState。
- `core:bootstrap`：各端设备实现和离线后端的装配。
- 离线阶段新增 `core:speech-local`（或等价独立模块）：SenseVoice/Piper/VAD 与模型管理，原生依赖不进入云协议模块。接口放在公共层以保持依赖单向。

流式 PCM 契约明确 bytes、sampleRate、channels、采样格式；播放会话包含 enqueue、正常 drain、立即 stop/close。保留现有整段接口作为兼容路径。队列归属 conversationId/turnId，晚到结果不能进入已经取消或切走的会话。

## 4. 分阶段执行与验收

### P0：锁定基线与契约

1. 检查未提交差异，记录现有语音相关测试与 Android/Desktop 构建结果；基线失败单独记录。
2. 整理可复用文件及最小依赖，固定 MiMo 请求/响应和音频格式样例，避免把“与 OpenAI 类似”当成协议完全兼容。
3. 定义 ASR/TTS 独立选择、PCM 格式、播放完成/取消语义和当前会话状态。

验收：文件与接口边界确定；旧功能回归清单、协议样例、平台能力矩阵可供后续任务使用。

### P1：云端基础能力迁移

1. 增加 MiMo ASR/TTS 协议分支、预置及模型/音色配置，先用整段结果闭环。
2. 接入目标 `Transcriber` / `Synthesizer`；录音、权限和发送复用现有实现。
3. 分离 ASR/TTS 选择与凭据引用：首次升级保留旧 provider/model/key，并保留现有 TTS 设备回退行为。源项目真实 Key 不复制到目标、不写入代码或文档。
4. 设置页提供可用性反馈、识别/朗读试用入口与错误提示；Key 继续走目标 SettingsStore。
5. 增加取消传递：停止播报同时取消合成网络任务，清理播放器，并丢弃旧会话结果。当前 `ModelSynthesizer.stop()` 只停播放器，需要补足请求生命周期。

验收：Android/Desktop 按住说话→识别→单聊/群聊发送→回复朗读可用；上滑取消、无声、权限拒绝、缺 Key、网络失败、切页、新输入打断和重启恢复均有正确行为；现有服务商回归通过。

### P2：低延迟流式播报

1. 先迁移 MiMo 音频事件解析、PCM16 对齐与 Android/Desktop PCM 播放器，让一段文本能边合成边播放。
2. 再迁移断句和队列；首句/后续句长度参考源端 32/80 字，作为可调初值，不视为已验证的最佳参数。
3. 接入 AppState 的文本输出事件：为每次回复和每个 AgentLoop 迭代建立边界。工具前文字可作为进度播报；重试、取消和最终回复按轮次去重，不能只监听消息快照差分。
4. 采用结构化协程与有界队列。不为每个 token 启动协程，不用无限 Channel；若需要背压，设计挂起事件消费路径，同时保证音频失败会解除等待并继续文本输出。
5. 单聊先验收，再接群聊；群聊按发言轮次顺序播报，先保留统一音色。禁止多个成员并发抢播放器。
6. 无流式能力的后端走整段兼容路径；途中失败保留文本、停止播报并提示，不重播已经念过的整段回复。

验收：首段音频在音频响应结束前可听到；启用文本流时首句在回复完成前可听到；顺序正确、尾句不漏、不重复、不播卡片/工具载荷；取消后不复活；队列上限和慢播放器可验证。记录首音延迟、总耗时和峰值队列占用，与 P1 相同文本、设备、网络条件比较，不预先承诺绝对延迟。

### P3：离线 ASR / TTS 与 VAD

1. 迁移 SenseVoice 与 Piper 的 Android/Desktop 实现，适配目标模型缓存目录、下载进度、校验、取消和资源释放。
2. 按需安装模型：缺模型/下载失败给出可操作提示，系统能力、离线模型、云端服务分别显示。离线失败不静默切换为付费云服务。
3. 移植 Silero VAD 与语音段裁剪；保持 ASR 输入 16 kHz PCM16，保留头尾缓冲，避免截掉轻声、短词和停顿。
4. 原生依赖分端配置，验证 sherpa/ONNX ABI 与发布包平台架构；源 build 按构建主机选 native 库，跨平台打包时需要改为按发布目标选择。
5. 盘点模型文件与运行时的许可/分发要求，决定应用内附带还是下载。VAD 失败可回退现有能量规则。

验收：模型准备好后，断网仍可完成识别和合成；首次下载、损坏文件、重启恢复、取消下载和重复录播均正常；设备上验证模型耗时、资源释放及包体变化。iOS 不展示尚未实现的离线选项。

### P4：iOS 与最终回归

1. 基础 iOS 接线可在 P1 同步准备：`PlatformInstall.ios.kt` 已安装 DeviceVoice，但当前 `MainViewController()` 未调用装配；Info.plist 尚缺麦克风/识别用途说明。补齐入口与说明并避免重复安装。
2. 使用目标现有系统 ASR/TTS 与整段云语音实现；流式 PCM 另写 AVAudioEngine 等原生实现，不能照搬源端抛错 stub。
3. 在 Mac 构建并在真机验收权限、AudioSession、后台/前台、耳机与中断；没有设备结果时明确标记待验收。
4. 更新语音文档和配置说明，按阶段保留可关闭的新后端/流式能力，便于回退。

## 5. 测试策略与协作安排

只增加能覆盖真实协议和生命周期风险的测试：MiMo JSON/鉴权、事件解析及半采样、非 2xx/提前断流；断句尾句/标点；慢播放器背压；取消后晚到事件；旧配置迁移；群聊轮次顺序。迁移源端相关测试样例，保留目标 `SpeechConfigTest`、`SpeechPayloadTest`、`VolcSpeechTest`、`VoiceTest`、`VoiceHoldTest`。

每阶段运行改动模块的测试与 Android/Desktop 编译；更改平台层/会话事件时跑对应调用方回归。端到端云测试使用显式配置的测试凭据，输出脱敏；计划阶段不消耗云调用费用。

主 agent 负责架构、接口、配置迁移、会话接线、集成审核和验收。GPT-6 Luna 接收明确文件范围的小任务：协议样例/解码、断句与测试、单个平台播放器、离线依赖盘点。接口冻结后再分配实现；同一文件只由一个 agent 修改。主 agent 处理 AppState/AgentLoop 等核心文件，子 agent 返回差异摘要、检查结果与未解决事项，不回传整份源码。优先单个 Luna，只有任务相互独立时再并行，以控制 token 成本。

源码盘点由 GPT-6 Luna 辅助完成，主 agent 负责整合。用户已授权按 P3 → P1 → P2 → P4 实施并可多个子 agent 并行；进展和最终检查结果另见迁移验收记录。
