# 语音回复播放完成与录音切换修复

日期：2026-10-05。

## 问题与原因

星伴语音对话会在 `sendCompanionVoice` 返回后等待 250 毫秒，再开启下一轮录音。
开启录音会停止所有回复朗读。原来的非流式播放器在启动音频后立即返回成功，系统
合成器也只等待请求入队，导致会话提前切回录音，将刚开始的回复截断。

这是播放生命周期与调用方预期不一致的问题；播放尾音也可能在提前开麦时被录入。
本次保留轮流录音和播放的会话方式，没有添加基于录音能量的开口打断或回声消除。

## 契约与实现

- `Player.play`：成功表示整段播放已完成；失败或被 `stop()` 中断返回 false；取消释放资源并继续传播取消。
- `Synthesizer.speak`：成功表示合成与播放均已完成，不能仅表示已排入系统播放队列。
- Android 文件音频等待 `MediaPlayer` 的完成/错误回调，异步准备，实例与临时文件按播放轮独立管理。
- Android 系统朗读等待 `UtteranceProgressListener.onDone`，用唯一 utterance ID 隔离迟到的结束、停止和错误回调。
- Desktop WAV 等待播放终止事件，MP3 等待解码播放工作线程完成。
- iOS 文件音频和系统朗读等待各自的 delegate 完成回调，并保留 delegate 强引用。

停止、替换及取消都会结束旧轮的等待并释放资源；旧轮收尾不释放新轮的播放器。
会话的 250 毫秒间隔现在发生在实际播放完成之后。
